# Oricon アルバム新譜情報 取得バッチ 仕様(構想) 2026-09-02

まだ未実装。要件整理と設計方針をまとめたもの。

## 目的

Oricon(https://www.oricon.co.jp/release/album/)のアルバム新譜リリース情報を
毎日取得し、今週から7週先までの範囲でテキスト化・メール送信する。

## 対象ページの調査結果(2026-09-02時点)

- 一覧ページはサーバー側で描画された素直なHTMLで、class名も安定している
  (`h5.title`・`h6.artist`・`td.cell-date`・`td.cell-price`・
  `td.cell-company`)。スクレイピングは比較的安全に実装できそう
- ページングは**日付ではなく「週」単位の連番**
  - `https://www.oricon.co.jp/release/album/`(無印) = 今週分
  - `.../p/1/` = 来週分、`.../p/2/` = 再来週分…と週が1つずつ進む
  - `.../p/-1/` = 先週分(逆方向)
  - ページ見出しに`YYYY年MM月DD日〜YYYY年MM月DD日発売`という週の範囲が
    入っているので、そこから実際の日付範囲を確認しながら必要なページ数を
    動的に判断できる
- 1ページ内は発売日ごとに`<h4>YYYY年MM月DD日 発売</h4>`で区切られ、
  その下に`<li class="jsc-block-ranking-detail">`が並ぶ(1件=1作品)
- ジャンル別タブ(邦楽・インディーズ・演歌歌謡曲・洋楽・ジャズクラシック・
  映画ドラマ・アニメ・その他)があるが、今回は**「すべて」ページ**
  (`/release/album/`)を使い、絞り込みはしない

## 取得する情報(1作品あたり)

- タイトル
- アーティスト名
- 発売日
- 価格
- レーベル/発売元
- 詳細ページURL(`/prof/.../products/.../`)

## 対象期間の考え方(2026-09-06更新: 8週→3週→2週に短縮)

- 「今月1日〜来月末日」という月ベースの動的範囲ではなく、
  **実行日を含む今週(無印ページ)から1週先(`p/1/`)まで、固定2ページ**を
  取得する方式にする
- 各ページ見出しの週範囲による動的な終了判定は不要になり、常に
  「無印ページ + `p/1/`」の固定2回フェッチで完結する
- 取得した全作品はそのまま対象とし、追加の日付範囲フィルタは行わない
  (ページング自体が期間の境界を兼ねるため)
- 初版は8週分(固定8ページ)としていたが、実データで1500件超と
  メールで見るには多すぎたため3週分に短縮、さらに2週分まで縮小した

## メール表示(2026-09-06追加)

- 発売日ごとに見出しでグループ化(従来通り)
- 各日付の下で、さらに**レコード会社/発売元ごと**に区分してまとめる
- レコード会社の区分はHTML `<details open><summary>...</summary>...</details>`
  によるアコーディオンにし、**デフォルトは開いた状態**にする
  (対応していないメールクライアントでは常時展開表示にフォールバックする)

## 出力・配信

- 毎日1回、メール送信(既存の`sumo_news_mail`等と同じ形式のHTML表)
- 発売日ごとにグループ化して表示(降順でも昇順でも、まずは日付昇順を想定)
- 該当0件の日でも「なかった旨」を送る(既存モジュール群の方針を踏襲)

## モジュール構成(案)

既存の「データ取得→JSON出力」「JSONを読んでメール化」の2モジュール分離を
踏襲する。

| モジュール | 役割 |
|---|---|
| `oricon_album.py` | 無印〜`p/7/`の固定8ページを取得し`output/oricon_album.json`に出力 |
| `oricon_album_mail.py` | 上記を読んでメール送信 |

## 実行タイミング

日ごとに内容が大きく変わるものではないため、毎日実行はしない。
`sumo_news_digest`と同じ**毎月10・20・30日のみ**(`day_of_month`ガード方式)
とする。時刻は既存の「小さな処理はまとめて同じ時刻に」という方針
(2026-08-24以降の運用)に合わせ、22:00の枠に相乗りする想定。

## 未確定・要確認事項

- 固定8ページ取得のため無限ループの心配は無くなった
- 同じ作品が日をまたいで複数回取得された場合の重複排除の要否
  (基本的に「今日時点のスナップショットを毎日送る」想定なので、
  前日と重複する内容が出るのは仕様として許容する想定。要否は実装時に
  再確認)
- サイト構造が変わった場合のフォールバック(現時点では未検討)
