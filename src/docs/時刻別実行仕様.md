# NightlyBatchNotify 時刻別実行仕様

最終更新: 2026-10-05(スケジュールと Grok 関連を現状に合わせて更新)

## 概要

NightlyBatchNotify は、Windows のタスクスケジューラから 15 分ごとに起動されるバッチです。
`main.py` が現在時刻を見て、`config.json` の `batch_schedule` に定義された時刻の
`±batch_window_minutes`(既定14分)以内かどうかを判定し、対象時刻内であれば処理を実行します
(それ以外は何もせず終了)。

タスクの実行時間の上限は **90分**(2026-10-06 に10分から変更)。Chrome を使うモジュール
(`radio_guest_check` 約18分、`web_watch`、`stock_x_trends_web_fetch`)は10分を超えることが
あるため。設定と確認方法は `new_pc_setup_instructions.md` の「5. タスクスケジューラに登録する」。

タスクスケジューラ自体は登録時刻(0:00)から1日中15分おきに動き続けるため、
`batch_schedule` に時刻を追加・削除するだけで実行タイミングを変更でき、
タスクスケジューラの再登録は不要です(`scheduler\install_scheduled_task.ps1` は
`config.json` の `batch_schedule` を毎回読み直して登録するので、時刻を大きく作り直す
場合のみ再実行すれば十分です)。

## 実行時刻・曜日・実行モジュール(統合スケジュール)

`batch_schedule` の各エントリは **時刻 → 曜日 → 実行モジュール** の3つを1つにまとめた
「スケジュール枠」です。バッチはこの順番で評価します: まず時刻が窓内か、次にその日の
曜日がこの枠の対象か、対象であれば最後にどのモジュールを動かすかを決めます。

```json
{
  "batch_schedule": [
    {"time": "05:00", "days": "all", "modules": ["post_x_magazine"]},
    {"time": "06:30", "modules": ["stock_x_trends_web_fetch"]},
    {"time": "06:45", "modules": ["stock_range", "stock_range_mail"]},
    {"time": "07:00", "modules": ["stock_nikkei", "stock_watchlist", "stock_dividend", "stock_ratings", "stock_turnover_watch", "nikkei_constituents", "market_news", "news_movers", "stock_x_trends", "ai_summary", "report_html", "mail_gmail"]},
    {"time": "09:30", "modules": ["stock_nikkei", "stock_watchlist", "market_news", "news_movers", "ai_summary", "report_html", "mail_gmail"]},
    {"time": "12:15", "modules": ["stock_nikkei", "stock_watchlist", "market_news", "news_movers", "stock_x_trends_eval", "stock_range_eval", "ai_summary", "report_html", "mail_gmail"]},
    {"time": "08:00", "modules": ["trade_review", "trade_review_mail"]},
    {"time": "09:45", "modules": ["trade_review", "trade_review_mail"]},
    {"time": "11:00", "days": "all", "modules": ["radio_guest_check"]},
    {"time": "13:00", "modules": ["trade_review", "trade_review_mail"]},
    {"time": "18:00", "modules": ["trade_review", "trade_review_mail"]},
    {"time": "17:30", "modules": [ /* 12:15と同じ */ ]},
    {"time": "22:00", "days": "all", "modules": [ /* 相撲・オリコン・キーワード/マーケット監視・note記事案・OneDrive/ディスク確認・claude_usage */ ]},
    {"time": "22:30", "modules": ["stock_x_trends_web_fetch"]},
    {"time": "23:00", "modules": ["stock_nikkei", "stock_watchlist", "market_news", "news_movers", "stock_range_eval", "stock_x_trends", "ai_summary", "report_html", "mail_gmail", "web_watch"]},
    {"time": "23:00", "days": "weekend", "modules": ["web_watch"]},
    {"time": "23:30", "days": "all", "modules": ["note_draft_post"]}
  ],
  "batch_window_minutes": 14,
  "batch_weekdays_only": true
}
```
(正確な内容は `config.json` を参照。上は 2026-10-05 時点の要約)

各エントリのフィールド:

- `time`(必須): `"HH:MM"`。省略不可。単純な `"HH:MM"` 文字列だけを書いた場合は、
  `days`・`modules`とも省略したものとして扱われます(例: `"07:00"` は
  `{"time": "07:00"}` と同じ)。
- `days`(省略可): この枠が有効な曜日。省略時は `batch_weekdays_only` の設定に従います
  (`true` なら平日のみ、`false` なら毎日)。指定方法は次項参照。
- `modules`(省略可): この枠で実行するモジュール名の配列。**省略した場合は
  `modules`(有効化フラグ)で `true` になっている全モジュールが対象**になります。

`modules` は基本的に**明示することを推奨**します。省略すると「有効な全モジュール」に
なるため、その枠に含めるつもりのないモジュールも、有効化フラグが `true` である限り
自動的に対象へ滑り込んでしまいます(モジュール側には可否判定を持たせない方針なので、
これを防ぐ手段は config 側の明示だけです)。現在の設定ではすべての枠で `modules` を明示しています。

現在の設定の内訳(2026-10-05 時点):

- `05:00` `post_x_magazine` — **毎日**(現在は有効化フラグが `false` のため実際には動かない)
- `06:30` `stock_x_trends_web_fetch`(Grok Web版で X の株トレンドを取得) — 平日のみ
- `06:45` `stock_range` / `stock_range_mail` — 平日のみ
- `07:00` 朝の総点検(市況・ニュース・Xトレンド・メイン配信) — 平日のみ
- `09:30` 寄り付き後の確認 — 平日のみ
- `12:15` 午前ニュースと午前相場のまとめ(Xトレンド・レンジの評価含む) — 平日のみ
- `13:00` `radio_guest_check`(Grok Web版でラジオのゲスト情報、3日に1回) — **毎日判定**
- `17:30` 夕方の市況まとめ(Xトレンド・レンジの評価含む) — 平日のみ
- `22:00` 相撲・オリコン・各種監視・note記事案・保守系 — **毎日**
- `22:30` `stock_x_trends_web_fetch` — 平日のみ
- `23:00` 夜の市場データ確認・Xトレンド — 平日のみ。最後に `web_watch`(Chrome でWebページ監視)
- `23:00`(土日) `web_watch` のみ — 同じ時刻の枠が複数ある場合は、今日の曜日が `days` に含まれる枠が使われる
- `23:30` `note_draft_post`(Chrome で note の下書き保存) — **毎日**

Chrome を操作するモジュール(`stock_x_trends_web_fetch` / `radio_guest_check` /
`web_watch` / `note_draft_post`)は Chrome が1つしかないため、時間帯が重ならないように配置しています。
Grok(Web版)の仕組みと利用上限は `docs/grok_web_spec_20261005.md`、
Webページ監視は `docs/web_watch_spec_20261006.md` を参照してください。

### `days` の指定方法

- 個別の曜日名(3文字・小文字): `"mon"`, `"tue"`, `"wed"`, `"thu"`, `"fri"`, `"sat"`, `"sun"`
  (単一の文字列でも配列でもOK。例: `"days": ["sat", "sun"]`)
- グループ指定(いずれも文字列): `"weekdays"`(月〜金) / `"weekend"`(土日) / `"all"`(毎日)
- 省略時は `batch_weekdays_only` の設定に従います

市況データが中心の枠は平日のみ、市況と無関係な枠(投稿・相撲・ラジオなど)は
`days: "all"` で土日も動くようにしています。

## モジュール内部での時刻自己判定は行わない

以前は `stock_x_trends`(`run_times`)や `post_x_magazine`(`run_times`)が、
`BATCH_SCHEDULE_KEY` 環境変数を見て「今回は実処理をするか」を自分で判定していましたが、
現在はこの仕組みを廃止しています。**実行するかどうかは `batch_schedule` の `modules`
指定だけで決まります**(方針: 実行可否の判断はすべて中央のスケジュール設定に一本化し、
モジュール個別の可否判定は持たせない)。

- `stock_x_trends` は `07:00` と `23:00` の `modules` にしか含まれていないので、
  09:30/12:15/17:30 ではそもそも呼び出されません(`report_html.py` は
  `output/stock_x_trends.json` の中身をそのまま表示するので、07:00 の結果が日中の
  メールに引き続き掲載されます)。
  なお `stock_x_trends` は `BATCH_SCHEDULE_KEY` を「実行するかどうか」ではなく
  「07:00 なら前の晩 23:00 の結果と合わせる」という処理内容の切り替えにだけ使っています。
- `stock_x_trends_web_fetch` は、実行するかどうかはスケジュールで決まりますが、
  `stock_x_trends.source` が `"web"` でないときは Grok を呼ばずに終わります
  (API 版に戻したときに無駄な Grok 呼び出しをしないため)。

いずれのモジュールも「呼ばれなければ何もしない」だけです。実行タイミングを変えたい場合は
`config.json` の `batch_schedule` だけを編集すれば十分です。

## モジュール概要

### `stock_nikkei`

日経平均、日経225先物、TOPIX 連動 ETF を取得します。

### `stock_watchlist`

注目銘柄の前日比と、直近10営業日分の日次変化、直近30営業日のレンジ内での現在位置を
取得します(yfinanceから30営業日分取得し、直近11本の終値から10日分の前日比を、
30営業日全体から30日高値・安値と現在値のレンジ内位置を算出。追加のAPI呼び出しは
発生しません)。レンジ内位置は`stock_range`が読み込んで別メールで送信します
(通常のレポートメールには含まれません)。

### `stock_range`

`stock_watchlist`が計算した30日レンジ情報(`output/stock_watchlist.json`の
`range_30d`)を読み込み、**通常の市況レポートとは別の専用メール**として送信します。
`21:30`枠(平日のみ)にのみ含まれており、1日1回だけ送信されます。`21:30`には
`stock_watchlist`自体は含まれていないため、**その日最後に`stock_watchlist`が
実行された時点(通常は12:15枠)のデータ**を使います。当日の最新値ではなく、
やや時間が経ったスナップショットになる点に注意してください。

各銘柄のカードには以下を表示します:
- 30日前比・前日比の変化額/率
- 30日高値・安値(日付付き)
- レンジ内の現在位置(0-100%、安値圏/中間/高値圏のラベル付き)
- 安値比(+X%)・高値比(-Y%): レンジ内位置を実際の%変化で表現
- 直近トレンド: 直近5営業日の値動きから上昇中/下降中/横ばいを判定
  (`RECENT_TREND_FLAT_THRESHOLD_PCT`=1.0%未満は横ばい扱い)

### `stock_dividend`

RYLD / SDIV の配当タイミングを扱います。

### `market_news`

日本株関連のニュースを Google News RSS(Google News / 株探 / Reuters の3系統)から
取得します。

### `news_movers`

ニュース本文から銘柄を照合し、値動き銘柄を作ります。

### `stock_x_trends`

Grok を使って、日本株に関係する X 上の話題銘柄やテーマを拾います。07:00 と 23:00 に実行します。

- 2026-10-02 から **Grok の Web 画面版** を使っています(`config.json` の
  `stock_x_trends.source: "web"`)。Grok の検索自体は30分前の `stock_x_trends_web_fetch`
  (06:30 / 22:30)が Chrome 経由で行い、`stock_x_trends` はその結果(キャッシュ)を読みます。
  キャッシュが120分より古ければ使いません。
- 07:00 は前の晩 23:00 の結果と朝の結果を、重複だけ除いて件数の上限なしで合わせます。
  朝の取得に失敗しても、前の晩の分は掲載されます。
- 実行ごとの結果は `output/history/stock_x_trends_runs/` に保存されます(無期限)。
- `source` を `"api"` に戻すと、従来の Grok API 版(`GROK_API_KEY` を使用)に戻ります。
- 詳細は `docs/grok_web_spec_20261005.md` を参照。

### `stock_x_trends_web_fetch`

06:30 / 22:30(平日)に、Grok の Web 画面(grok.com)へ X の株トレンドを質問し、
結果を `state/stock_x_trends_web_cache.json` に保存します。Grok の操作は
`modules/grok_web.py`(Claude が Chrome を操作)を使います。Chrome の起動・
Claude in Chrome 拡張の接続・grok.com へのログインが前提です。

### `ai_summary`

市場データとニュースを AI で要約します。

### `post_x_magazine`

`config.json` の `post_x_magazine.magazines` に登録されたテーマ別マガジンから記事を
ローテーション選択し、Gemini(失敗時は本文ベースのフォールバック)で5本のXスレッドを
生成して投稿します。

- 1本目: フック(数字・体験談ベースの書き出し)+ 導入
- 2本目: 内容の具体点
- 3本目: 実用性・気づき
- 4本目: 読後の持ち帰り + 読者への問いかけ(返信を誘う)
- 5本目: マガジン紹介(他のテーマ別マガジンをプロフィール固定ツイートで案内)+ ハッシュタグ

`POST_X_MAGAZINE_PREVIEW=1` / `POST_X_MAGAZINE_NOTIFY_ONLY=1` を立てるとXには投稿せず、
生成結果のみメール通知できます。成功・失敗いずれの場合も通知メールが送られ、本文には
5投稿すべてが並び、失敗時はどの投稿で失敗したか(`n/5`)と理由が表示されます。

手動で単体実行したい場合は `run_post_x_magazine.bat`(`main.py --force --schedule 07:30`
を実行し、`batch_schedule` の `07:30` エントリの `modules` 指定により post_x_magazine
のみが動く)を使います。

### `report_html`

各モジュールの出力 JSON を HTML にまとめます。

### `mail_gmail`

HTML レポートを Gmail で送信します。`post_x_magazine` の通知メールもこのモジュール内の
`send_html_mail()` を共有して送信します。

### `post_x_note`

note 記事を X に投稿する旧世代の独立ランナーです。`post_x_magazine` に役割を引き継いだため
`modules` には登録されておらず、現在は常時OFFです(`run_post_x_note.bat` から手動実行は可能)。

## 補足

- `main.py` は `--force --schedule HH:MM` で任意の時刻枠を強制実行できます(時刻チェック省略)
- `run_force.bat` はテスト用に07:00/09:30/12:15/22:45または全モジュールを選べる対話式バッチです
  (07:30/21:00枠は未対応。post_x_magazine単体は `run_post_x_magazine.bat` を使ってください)。
  ※ 22:45 枠は現在のスケジュールには無いため、選んでも該当する枠がありません
- Grok(Web版)を手で1回試すときは `python -m modules.grok_web "質問" --out output/xxx.json`、
  利用状況の確認は `python -m modules.grok_web --usage`
