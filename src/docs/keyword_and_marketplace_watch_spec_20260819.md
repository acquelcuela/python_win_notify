## 全体方針(2機能共通)

- 既存のバッチ構成(`stock_range.py`/`stock_range_mail.py`、`sumo_news.py`/
  `sumo_news_mail.py`と同じ「データ取得→JSON出力」「JSONを読んでメール化」の
  2モジュール分離)を踏襲する
- `sumo_news_mail`と同じ方針で、該当0件の日も「なかった旨」のメールを送る
  (サイレントスキップは障害と見分けがつかないため)
- 新規モジュールは`main.py`の`MODULE_ORDER`と`config.json`の`modules`に追加、
  `batch_schedule`に実行時刻を追加する
- **月次実行について**: `main.py`の`batch_schedule`は時刻+曜日判定のみで、
  「月1回」「毎月何日」という条件を直接は扱えない。そのため月次バッチは
  モジュール内部で`datetime.now(JST).day`をチェックし、対象日以外は
  `status: skipped`で早期returnする(該当日にバッチ実行タイミングが来た時だけ
  中身を実行する)方式にする

## 機能A: 気になるキーワード 月次検索通知

### 目的

登録したキーワードについて、月1回まとめて関連ニュース・記事を検索し、
メールで通知する。日々の値動き系レポートとは別に、緩やかに継続ウォッチしたい
トピック用。

### 情報源

Google News RSS(既存の`market_news.py`・`sumo_news.py`と同じ方式)。
実装済みのRSS取得・パース処理をそのまま流用できるため、低リスク・低コスト。

### 設定(config.json案)

```json
"keyword_watch": {
  "queries": ["キーワード1", "キーワード2"],
  "day_of_month": 1,
  "lookback_days": 31,
  "max_items": 20
}
```

- `queries`: 検索キーワードのリスト(ユーザーから追って提供)
- `day_of_month`: 実行日(例: 毎月1日)
- `lookback_days`: 前回実行からの期間相当。月次なので31日を目安にする

### 重複排除

月をまたいで同じ記事が再度ヒットする可能性があるため、`state/keyword_watch_seen.json`
に通知済みURL(またはタイトル+日付のハッシュ)を保持し、既出は除外する。
保持期間は数ヶ月分(検討中、目安90日)。

### モジュール構成

| モジュール | 役割 | 実行タイミング |
|---|---|---|
| `keyword_watch.py` | Google News RSS検索・`output/keyword_watch.json`出力 | 例: 毎日07:15にバッチ起動、内部で`day_of_month`一致時のみ処理 |
| `keyword_watch_mail.py` | `keyword_watch.json`を読んでメール送信(0件でも送信) | 同上 |

## 機能B: ヤフオク・メルカリ 新着出品監視

### 目的

登録キーワードに一致する新着出品を1日1回チェックし、前回チェック以降に
増えた分だけメールで通知する。

### データ取得方法(要確認事項が多い)

**公式API**はヤフオク・メルカリともに、外部開発者向けの一般公開キーワード検索
APIは実質提供されていない(把握している範囲)。選択肢は以下:

1. **非公式API・内部エンドポイントを利用する**(今回はこの方針で進める、ユーザー了承済み)
   - ヤフオク: 検索結果ページがRSS/Atom形式で取得できる可能性がある
     (要検証。過去は検索結果のフィード配信があったが、現在も生存しているか
     未確認)
   - メルカリ: 公式に提供されたAPIは無い。アプリ/Web版が内部的に叩いている
     検索APIをリバースエンジニアリングして使う非公式ライブラリ(例:
     mercapi等のOSS)が存在するが、エンドポイント仕様がメルカリ側の都合で
     頻繁に変わり得る
2. HTMLスクレイピング(フォールバック。非公式APIが機能しない場合の代替)

いずれの方法も**利用規約上のグレーゾーン**である点は明記しておく
(個人の私的利用・低頻度アクセスであることが前提)。

### リスク・注意点

- エンドポイント仕様変更で突然動かなくなる可能性が高い(既存モジュールより
  保守コストが高い機能になる見込み)
- 短時間の連続アクセスやIPブロックを避けるため、1日1回・キーワードあたり
  1回程度の低頻度アクセスに留める
- 上記の理由から、**着手前にヤフオク側のRSS配信の生存確認、メルカリ側の
  非公式エンドポイント調査を先にやる**(調査だけ先行させて、実現可否を
  確認してから実装するのが安全)

### 設定(config.json案)

```json
"marketplace_watch": {
  "keywords": [
    {"keyword": "検索語1", "platforms": ["yahoo_auction", "mercari"]}
  ],
  "max_items_per_keyword": 20
}
```

### 重複排除

`state/marketplace_watch_seen.json`に、キーワード×プラットフォームごとに
既知の出品ID一覧を保持。前回チェック時点になかったIDだけを「新着」として
通知する。保持件数はキーワードあたり直近数百件程度を目安に古いものから削除。

### モジュール構成

| モジュール | 役割 | 実行タイミング |
|---|---|---|
| `marketplace_watch.py` | ヤフオク・メルカリ検索、新着抽出、`output/marketplace_watch.json`出力 | 1日1回(例: 08:00) |
| `marketplace_watch_mail.py` | `marketplace_watch.json`を読んでメール送信(新着0件でも送信) | 同上 |
