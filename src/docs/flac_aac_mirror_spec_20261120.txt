FLAC→AAC ミラー変換バッチ 仕様書
作成日: 2026-11-20
状態: 仕様合意済み・未実装（実装開始はユーザーの指示待ち）

■ 目的
外付けHDD上の FLAC ライブラリ（アーティスト/アルバム構成）を、同じディレクトリ構成で
AAC(.m4a) に変換したミラーを作り、夜間バッチで FLAC 側の変更に追従させる。
FLAC 側が親。AAC 側は FLAC 側に従う。

■ 対象フォルダ
ベース: E:\data@T1TBEXFAT\non_syncthing\【music】\
  - flac_2025               561曲 / 15.8GB
  - flac_2026               256曲 /  7.9GB
  - flac_alac_convert_2026  238曲 /  7.7GB
  合計 1,055曲 / 31.4GB（2026-11-20 時点）
対象外: 【削除OK】apple_lossless_convert_済（FLACが11曲あるが削除予定のため）

■ 出力先（提案。実装時に最終確認）
【music】\aac\<元フォルダ名>\<アーティスト>\<アルバム>\<曲>.m4a
例: flac_2025\Artist\Album\01 Song.flac → aac\flac_2025\Artist\Album\01 Song.m4a
元フォルダごとに分けるので、同じアルバムが複数の元フォルダにあっても衝突しない。

■ 設定（.env）
FLAC_ROOTS=<元フォルダのパスをセミコロン区切りで指定>
AAC_ROOT=E:\data@T1TBEXFAT\non_syncthing\【music】\aac
元フォルダを追加するときは FLAC_ROOTS に追記するだけでよい（例: 将来の flac_2027）。

■ 変換
- ツール: ffmpeg（標準の AAC エンコーダー）
- ビットレート: 256kbps、拡張子 .m4a
- タグ（曲名・アーティスト・アルバムなど）と、埋め込みのジャケット画像を引き継ぐ
- 対象は .flac のみ。cover.jpg / .cue / .log などはコピーしない
- CPUコア数に応じて並列に変換する
- ffmpeg は未インストール（winget install --id Gyan.FFmpeg -e で導入予定）

■ 同期のルール（バッチごとに両方を走査して差分を判定）
- 追加: FLAC あり / AAC なし            → 変換
- 変更: FLAC の更新日時 ≠ AAC の更新日時 → 変換し直す
- 削除: AAC あり / 元の FLAC なし        → AAC を削除
- リネーム・移動: 削除＋追加として扱う（再変換になる）
- 変換後、AAC の更新日時を FLAC と同じ値にそろえる（次回の変更判定に使う）
- exFAT は日時を細かく記録できないため、差が2秒以内なら同じとみなす
- 削除によって空になったフォルダは AAC 側から消す
- 管理用のDBや状態ファイルは持たない

■ 安全策
- 目印ファイル: 元フォルダごとに .flac_root を置き、これがあるフォルダだけを処理する
  （外付けHDDはドライブ文字が変わることがあるため）
- HDD が見つからない / 目印ファイルがない: 変換も削除もせず、スキップした旨をメールで通知
- 一括削除の防止: 元フォルダのFLACが0件のときや、削除件数が多すぎるとき
  （しきい値は実装時に決める）は削除を行わずに中止し、メールで通知
- 書きかけファイル対策: いったん .tmp に書き出し、完了してから正式な名前に変える
- 二重起動の防止: ロックファイルを使う
- FLAC 側には一切書き込まない（読み取りのみ）

■ 実行タイミング
- 毎晩 02:00 ごろ。既存の config.json のスケジュールの仕組みに乗せる
- 05:00〜05:15 は回線が切れるため、メール送信がその時間に重ならないようにする
- 所要時間の見込み: 初回 30〜40分程度、2回目以降の差分チェックは数秒

■ 通知（既存の modules/mail_gmail.py を使う）
- 本文: 件数のサマリー（追加 / 更新 / 削除 / 失敗）と、失敗したファイルの一覧
- 添付: 処理した全ファイルの一覧（.txt）
- 処理対象が0件の夜はメールを送らない
- スキップや中止（HDDなし・削除が多すぎる等）のときは0件でも通知する

■ 導入の手順（実装時）
1. ffmpeg をインストールする
2. 3つの元フォルダに .flac_root を置く
3. .env に FLAC_ROOTS / AAC_ROOT を追加する
4. ドライランで実行する（変換・削除はせず、やる予定の内容だけをメールする）
5. 内容を確認してから本番で実行し、初回の全変換を行う
6. 毎晩のスケジュールに登録する

■ 実装時に確認すること
- 出力先の構成（上記の「出力先（提案）」）でよいか
- 一括削除を止めるしきい値
