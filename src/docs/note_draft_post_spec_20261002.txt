note 下書き自動保存 仕様・使い方 (2026-10-02)
================================================

■ 概要
  事前に用意した「指示書」を、バッチから Claude(claude -p --chrome)に渡し、
  Chrome を操作して note.com に【下書き保存まで】行う。
  有料設定・画像追加・ハッシュタグ・マガジン設定・公開はユーザーが手動で行う。
  仕組みは modules/grok_web.py(Grok の Web 画面を Claude で操作)と同じ。

■ ファイル構成
  modules/note_draft_post.py        本体
  note_drafts/queue/                指示書を置く場所(ここにファイルがあれば実行対象)
  note_drafts/queue/_template.md    指示書のひな形("_" で始まるファイルは処理しない)
  note_drafts/done/                 下書き保存に成功した指示書(日付付きで移動)
  note_drafts/failed/               失敗した指示書(日付付きで移動)
  note_drafts/README.md             使い方メモ
  state/note_draft_runs.json        1件ごとの実行記録(所要時間・使用率の増分)
  output/note_draft_post.json       直近の実行結果
  ※ 指示書は個人コンテンツのため git 管理外(README と _template.md のみ管理)

■ 実行タイミング
  ・毎日 23:30 に起動(土日含む。config.json の batch_schedule)
  ・以下をすべて満たすときだけ実行する
      1. note_drafts/queue/ に指示書(.md、"_" 始まり以外)がある
      2. 週次リミットのリセットまで 24 時間以内
         → 実質「週1回、リセット前夜」(例: リセットが 10/7 6:00 なら 10/6 23:30)
      3. 週次使用率 90% 未満、かつセッション使用率 80% 未満
  ・使用率は claude -p "/usage" で取得(Claude 使用状況メールと同じ方法)
  ・23:30 にしたのは 22:30 の Grok 取得(同じく Chrome を使う)と重ならないため

■ 1回の処理
  ・ファイル名順に最大 3 件
  ・1件ごとに使用率を再チェックし、上限を超えたらそこで打ち切り(残りは次週)
  ・1件あたりのタイムアウト 900 秒(全体の上限 3000 秒)

■ Claude に指示する内容
  1. note.com を開き、ログイン済みか確認(未ログインなら何もせずエラー報告)
  2. テキスト記事の新規作成画面でタイトルと本文を入力
     ・Markdown の見出し(##)・箇条書き(-)・太字(**)は note の書式に変換
     ・本文の文言は一字一句変えない(要約・言い換え禁止)
  3. 「下書き保存」する
  ・絶対に公開しない(「公開に進む」「投稿する」は押さない)
  ・価格・有料ライン・ハッシュタグ・画像・マガジンは設定しない
  ・想定外の画面(規約同意・確認ダイアログ等)が出たら進めずエラー報告
  ・使えるツールは Chrome 操作(claude-in-chrome)のみに限定

■ 指示書の書き方
  _template.md をコピーし、"_" で始まらない名前で queue/ に置く
  (例: queue/2026-10-05_高配当株まとめ.md)

  ---
  title: 記事タイトル
  price: 500円
  paid_line: 「## ここから有料」の見出しの直前
  hashtags: #高配当株 #NISA #配当生活
  magazine: 高配当株レビュー
  images: 見出し画像は○○
  memo: 自分用メモ
  ---
  ここから本文(Markdown)

  ・Claude が入力するのは title と本文だけ
  ・price / paid_line / hashtags / magazine / images / memo は参考情報。
    結果メールに「手動で仕上げる項目」として表示される(すべて省略可)
  ・title を省略するとファイル名がタイトルになる

■ 結果メール
  件名: note下書き 成功数/件数 YYYY-MM-DD
  1件ごとに以下を表示
  ・成功/失敗、ファイル名、所要時間
  ・下書きの URL
  ・消費量: セッション ○% → ○% (+○) / 週次 ○% → ○% (+○)
  ・手動で仕上げる項目(価格・有料ライン・ハッシュタグ・マガジン・画像・メモ)
  ・失敗時はエラー内容

■ 失敗したとき
  ・指示書は failed/ に移動する(半端な下書きが毎週重複して作られるのを防ぐため)
  ・エラー内容はメールに表示。直して queue/ に戻せば次回また実行される
  ・note の画面変更などで動かなくなった場合も、メールのエラーで分かる → 都度対処

■ 手動テスト(タイミング判定をスキップして今すぐ実行)
  前提: Chrome 起動中・Claude in Chrome 拡張が接続済み・note にログイン済み
    cd src
    .venv\Scripts\python.exe -m modules.note_draft_post --force
  ※ 使用率の上限チェックは --force でも有効

■ 設定値(config.json の note_draft_post)
  run_within_hours_before_weekly_reset : 24    リセット何時間前から実行するか
  max_week_used_pct                    : 90    週次使用率がこれ以上なら実行しない
  max_session_used_pct                 : 80    セッション使用率がこれ以上なら実行しない
  max_posts_per_run                    : 3     1回に処理する最大件数
  timeout_seconds_per_post             : 900   1件あたりのタイムアウト(秒)

■ 前提・注意
  ・PC が起動していて、ユーザーがログオン中であること(Chrome と同じデスクトップで動かすため)
  ・Chrome が起動していて note にログイン済みであること
  ・画面操作は文章生成より Claude の使用量が多い。最初の数回は結果メールの
    「消費量」で 1 件あたりの使用量を確認し、max_posts_per_run などを調整する
  ・note の利用規約はユーザー確認済み

■ 今後の予定
  ・最初の数回は --force で手動テストし、1件あたりの消費量を確認
  ・問題なければ、週1回の自動実行に任せる
  ・慣れてきたら、公開までの自動化を検討(現時点では下書きまで)
