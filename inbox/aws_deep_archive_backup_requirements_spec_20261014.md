## 1. 目的

ほとんど見ないが手放したくないCD・DVD・写真などのデータを、安く長期間保管する。自宅のHDDだけだと、HDDが壊れたら失われるため。

位置づけ：中身は買い直せるものが中心で、「できれば失いたくない」程度。失われても致命的ではない。

## 2. 要件

### 2.1 機能要件

| # | 要件 |
| --- | --- |
| F1 | データを、期限なしで保管し続けられる |
| F2 | 必要なときに、ファイル単位（DVD 1枚、写真の一定期間分など）で取り出せる |
| F3 | 何を預けているかの一覧を、取り出さずにいつでも確認できる |
| F4 | あとからデータを追加できる（DVDは今後も増える見込み） |
| F5 | PCが壊れても、別の端末からアクセスを取り戻せる |

### 2.2 非機能要件

| # | 要件 | 目標 |
| --- | --- | --- |
| N1 | 費用 | 保存料金は1TBで年2,000円程度まで。初回分（約57GB）は月10円程度 |
| N2 | 取り出し頻度と速さ | 年1回、5GB程度。取り出しに2日かかってもよい |
| N3 | 耐久性 | HDD単体より高いこと |
| N4 | 安全性 | 操作ミスやアクセスキーの流出でデータが消えないこと。外部に公開されないこと |
| N5 | 通信量 | 1日の送信は5GBまで（プロバイダBBIQへの配慮） |
| N6 | 手間 | 年に数回の操作で済み、手順書のコマンドを貼り付けて実行できること |

### 2.3 制約

- 作業環境はWindows＋Git Bash（作業用ドライブ `E:`、exFAT）。
- 上り回線は実測で約1.4MiB/s（約12Mbps、1時間で約5GB）。
- AWSアカウントは既存のもの（root、MFA設定済み）を使う。同じアカウントでEC2とRoute 53も使っている（先月の利用額$1.11）。

### 2.4 対象外

- 再ダウンロードできるもの（macOSのインストーラーなど）は保管しない。
- 普段見るための保管（すぐに再生・閲覧するもの）は対象外。手元のHDDで行う。
- 本人の死亡後に家族が取り出すことは想定しない（エンディングノートに1行残すのみ）。

## 3. 仕様

### 3.1 構成

| 項目 | 値 | 理由 |
| --- | --- | --- |
| サービス | Amazon S3 | 耐久性99.999999999%（3か所以上に自動で複製） |
| ストレージクラス | S3 Glacier Deep Archive | 最安。取り出しに時間がかかるが要件N2を満たす |
| リージョン | us-east-1（バージニア北部） | Deep Archiveの保存料金が東京の約半額。取り出しが元々遅いので距離は問題にならない |
| バケット | `kaeru-media-archive`（グローバル名前空間） | — |
| パブリックアクセス | すべてブロック | 要件N4 |
| 暗号化 | SSE-S3 | 追加料金なし |
| バージョニング | 無効 | 削除権限がないので不要。上書きのたびに料金が増えるのを避ける |

### 3.2 ライフサイクルルール（`to-deep-archive`、バケット全体）

| アクション | 設定 | 目的 |
| --- | --- | --- |
| 現行バージョンを移行 | 作成後0日でGlacier Deep Archiveへ | `--storage-class` の付け忘れへの保険。128KB未満のファイル（一覧など）は移動しない |
| 不完全なマルチパートアップロードを削除 | 7日後 | 送信が途中で止まったときの断片への課金を防ぐ |

### 3.3 アクセス管理

| 項目 | 仕様 |
| --- | --- |
| rootユーザー | MFA設定済み。普段は使わない。コンソールでの確認と、緊急時の削除・キーの再発行だけに使う |
| 操作用ユーザー | IAMユーザー `archive-cli`。コンソールへのログイン不可。アクセスキーのみ |
| 権限（インラインポリシー `archive-bucket-only`） | `kaeru-media-archive` に対して ListBucket、GetBucketLocation、PutObject、GetObject、RestoreObject、AbortMultipartUpload のみ。**削除権限（DeleteObject）なし**（動作確認済み） |
| アクセスキー | パスワードマネージャーに保存。PCを失ったら作り直す |
| 予算アラート | 月$3（アカウント全体）。85%・100%・予測100%超えでメインのメールアドレスに通知 |

### 3.4 データの仕様

| 項目 | 仕様 |
| --- | --- |
| 保存場所（プレフィックス） | `dvd/`（DVD）、`pic/`（写真）、`catalog/`（一覧など、任意） |
| ファイル名 | 英数字・小文字・アンダースコア（日付部分のみハイフン可）。日本語は使わない |
| まとめ方 | DVDは1枚＝1つのtar（VIDEO_TSごと）。写真は撮影月ごとにまとめたtar。圧縮はしない（`tar -cvf`） |
| 1ファイルの大きさ | 通常1〜2GB、上限4GB。DVD 1枚のように分けると使えなくなるものに限り、例外として15GBまで。`split` での機械的な分割はしない |
| 写真のファイル名 | `photos_<端末>_<開始年月>_<終了年月>.tar`（例：`photos_kaerui_iphonese2_2022-09_2022-12.tar`） |
| 不要ファイル | Macの `._*`、`.DS_Store`、Windowsの `Thumbs.db`、`desktop.ini` は入れない |
| 上書き | 禁止。送ったファイルは作り直さず、追加分は新しい名前で送る |
| ハッシュ | 取らない。転送中の破損はAWS CLIが自動で照合する |

### 3.5 運用の仕様

| 作業 | 方法 |
| --- | --- |
| アップロード | AWS CLIの `aws s3 sync … --storage-class DEEP_ARCHIVE` のみ。GUIツール（WinSCPなど）は使わない。1日5GBまで |
| 一覧の確認 | `aws s3 ls`（取り出さずに見られる）。送ったあとは `aws_s3_deep_archive_filelist_YYYYMMDD.txt` を作り、Googleドライブに保存する |
| 取り出し | 復元リクエスト（Bulk、一時コピーは7日間）→ 2日後にダウンロード（`--force-glacier-transfer`） |
| 点検 | 年1回。一覧、クレジットカードの有効期限、予算アラート、rootでログインできるかを確認する |

## 4. 費用（us-east-1）

| 項目 | 単価 | 初回分（約57GB）の目安 |
| --- | --- | --- |
| 保存 | $0.00099/GB/月 | 月約9円、年約110円 |
| アップロード | 受信は無料。リクエスト料は約$0.05/1000件 | 数円 |
| 取り出し（Bulk） | $0.0025/GB | DVD 1枚（4.4GB）で約2円 |
| 一時コピー（7日間） | S3 Standardの日割り | DVD 1枚で約5円 |
| ダウンロード | 月100GBまで無料。超えた分は約$0.09/GB | 通常は無料枠内 |
| 最低保存期間 | 180日。それより前に消すと残りの日数分を請求される | — |
| 1ファイルごとの上乗せ | 40KB | 1〜2GBのファイルでは無視できる |

参考：1TBなら保存は年約1,950円。全部を取り出して手元に戻すと約13,000円（ほぼダウンロードの転送料）。

## 5. リスクと対策

| リスク | 対策 |
| --- | --- |
| クレジットカードの期限切れで支払いが止まり、アカウントが閉鎖されてデータが消える | カードを更新したらAWS側も更新する。年1回の点検で確認する |
| rootにログインできなくなる | メールアドレス・パスワード・MFAの3つを管理する。MFAの予備を用意する |
| アクセスキーの流出・操作ミス | 削除権限を付けない。流出が疑われたらキーを無効にして作り直す |
| GUIでうっかり上書き・Standardでアップロードする | GUIツールを使わない。ライフサイクルルールの保険 |
| 本人の死亡などで支払いが止まる | 停止 → 閉鎖 → 猶予期間（通常90日）のあとに自動で削除される。エンディングノートに1行残す |
| 回線の使いすぎ | 1日5GBまでに抑える |
