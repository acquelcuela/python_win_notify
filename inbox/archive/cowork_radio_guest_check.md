# Cowork向け指示: radiko・NHKラジオ(らじる★らじる)・音泉 番組ゲスト情報まとめ

Coworkに貼り付けて実行してもらう用の指示文。実行のたびにこのファイルの
内容をコピペして渡す(スケジュール化はしない、都度手動でGoする運用)。

---

## フォロー中の番組リスト(radiko)

ユーザーが個別に追っているradiko番組のリスト。radikoの検索は、まず
このリストの番組を名指しでゲスト確認し(Stage1)、そのあとリスト以外の
番組を広く探す(Stage2)、という2段階で行う([やってほしいこと]参照)。

リストの更新は、ユーザーが新しいリストを提示したタイミングで、この
セクションをまるごと置き換える運用とする(ユーザーが都度渡す方式では
なく、指示書に固定で書き込む方式)。

(番組リストは個人情報のため、バッチ版では src/config.local.json(git管理外)の
radio_guest_check.followed_programs に移した。)

```
ChromeでX(x.com)を開き、Grok(x.com/i/grok)を使って、以下3つの
ラジオ・音声配信サービスの番組ゲスト情報を検索してください。
対象期間は「本日から10日後まで」です(単日だけだと、まだ発表されて
いるだけでその日の番組表に反映されていないゲスト情報を取りこぼす
ため、範囲を広げています)。

対象サービス:
1. radiko
2. NHKラジオ(らじる★らじる:NHK第1・NHK第2・NHK-FMを配信するアプリ)の
   音楽・バラエティ番組
   (特に「ミュージックライン」はNHK-FMの月〜金 帯番組で、平日は毎日

   https://www.nhk.jp/p/ml/rs/Z9WGYY3GP5/ )
3. 音泉

やってほしいこと:
(radikoは「2.本体検索+3.言い換え検索+4.情報抜き出し」をサービスの基本単位とし、
これを「Stage1: フォロー中番組の確認」「Stage2: リスト外の探索」の2段階に分けて
実行する[0.参照]。NHKラジオ・音泉は言い換え検索(3.)を行わず、「2.本体検索+
4.情報抜き出し」を1回だけ実行すればよい[7.で理由を説明])

0. 【radikoのみ2段階検索(Stage1/Stage2)】radikoについてのみ、検索を以下の
   2段階に分けて行う(NHKラジオ・音泉はこの分け方をしない。従来通り1回のみ):
   - Stage1(フォロー中番組の確認): 「フォロー中の番組リスト」(このファイル
     冒頭)に載っている番組について、番組名を名指しでGrokに渡し、対象期間内
     にゲスト出演があるかを確認する。2.~3.の「本体検索+言い換え検索」を
     1セットだけ実行する(Stage2と違い、2セット化・マージは行わない。
     番組名を指定する検索はGrokの回による結果のブレが本体検索より小さいと
     見込まれるため)
   - Stage2(リスト外の探索): フォロー中の番組リストは特に意識せず、従来
     通りradiko全体を対象に広く探す。2.~4.を1セットとし、7.の通り2セット
     実行してAI(Claude)でマージする。Stage1でカバー済みの番組が
     Stage2でも見つかって構わない(重複してもよい。8.のまとめ段階で
     Claude側が統合する)
   (背景: 2026/9/17に、ユーザーから「気になる番組リストのゲストを
   先に確認し、そのあとリスト以外を探す2段階にしたい」という要望があり、
   採用した。名指し検索の方が個別番組のゲスト精度が上がる一方、リスト外の
   発掘は従来の広域検索とほぼ同じ性質のため、Stage2は従来通り2セット+
   マージを維持する。補足メモも参照)
1. x.com/i/grok を開く(radikoはStage1用に1つ、Stage2用に2つ[2セット目は
   独立スレッド]の計3スレッドになる。NHKラジオ・音泉はそれぞれ1スレッドで
   よい。同じスレッドの続きだと直前の内容に引っ張られて、同じような回答に
   なりやすいため、Stage2の2セット目やNHK・音泉のスレッドは基本的に新しい
   会話スレッド/新規チャットで開始する)
2. サービスごとに、以下のような検索を行う(例。本日の日付と、10日後の
   日付の両方を明記すると精度が上がる。放送日と「実際に聴けるURL」も
   合わせて聞くこと。番組の紹介記事・公式お知らせページのURLではなく、
   radiko/らじる★らじるでそのまま再生できるURLが欲しいと明示する):
   - radiko Stage1(フォロー中番組の確認)の質問例(「フォロー中の番組
     リスト」の内容をそのまま質問文に貼り付ける):
     「以下のradiko番組について、本日(YYYY年M月D日)から10日後(YYYY年M月D日)
     までの間にゲスト出演の発表があるか、番組ごとに教えてください。ゲスト
     がいる場合は放送日・ゲスト名・radikoで実際に聴けるURL(ライブURL:
     https://radiko.jp/#!/live/[放送局ID]、またはタイムフリーURL:
     https://radiko.jp/#!/ts/[放送局ID]/[YYYYMMDDHHMMSS])を、いない場合は
     『ゲスト情報なし』とだけ、番組ごとに教えてください。
     [ここに「フォロー中の番組リスト」を番組名/放送局/放送時間の形式で
     列挙]」
   - radiko Stage2(リスト外の探索)の質問例(フォロー中の番組リストには
     触れず、従来通りradiko全体を対象に聞く):
     「radiko 本日(YYYY年M月D日)から10日後(YYYY年M月D日)までの番組表・
     告知で、ゲスト出演が発表されている番組を教えて。それぞれ放送日を
     明記した上で、radikoで実際に聴けるURL(ライブURL:
     https://radiko.jp/#!/live/[放送局ID]、またはタイムフリーURL:
     https://radiko.jp/#!/ts/[放送局ID]/[YYYYMMDDHHMMSS])も分かれば
     教えて。番組の紹介記事URLではなく再生用URLが欲しい」
   - 「NHKラジオ(らじる★らじるで配信されているNHK第1・NHK第2・NHK-FM)の
     本日(YYYY年M月D日)から10日後(YYYY年M月D日)までの音楽番組・バラエティ
     番組で、ゲスト出演が発表されている番組を教えて。それぞれ放送日を
     明記した上で、らじる★らじるで実際に聴けるURL(ライブURL:
     https://www.nhk.or.jp/radio/player/?ch=r1(第1)/?ch=r2(第2)/
     ?ch=fm(FM)、または聴き逃しURL:
     https://www.nhk.or.jp/radio/ondemand/detail.html?p=... )も分かれば
     教えて。nhk.jpの番組紹介ページではなく再生用URLが欲しい」
   - 「音泉(インターネットラジオ)の本日(YYYY年M月D日)から10日後
     (YYYY年M月D日)までに配信される番組で、ゲスト出演が発表されている
     番組を教えて。それぞれ放送日(配信日)を明記した上で、その番組が
     聴けるonsen.agの番組ページURLも分かれば教えて」
   (NHKは対象ジャンルを「音楽・バラエティ」に絞る。ニュース・報道・教養・
   語学講座・スポーツ中継などジャンルの番組は対象外でよい。どの番組が
   らじる★らじるで実際に配信されているかの厳密な判定は不要で、Grokの
   回答に出てきたNHK第1・第2・FMの音楽/バラエティ番組をそのまま採用してよい)
3. 【言い換え検索(radikoのみ)】radiko(Stage1・Stage2とも)は、検索(2.)を
   1回行った後、同じ会話(スレッド)内で、言い回しを変えた確認質問を追加で
   もう1回投げる。NHKラジオ・音泉はこの言い換え検索を行わない(2026/9/17に
   1回のみに簡略化した。理由は7.参照)。
   (背景: Grokの検索は毎回ウェブを新たにクロールしてLLMが要約する
   仕組みのため、まったく同じ質問文で聞いても、回によって拾える情報・
   拾えない情報にばらつきが出ることが分かっている。実例として、
   2026/8/30の検索ではNHKラジオ第1『らじらー！サンデー』9/6放送分の
   乃木坂46出演情報を拾えていたが、2026/9/1・9/5の検索では同じ情報が
   再確認できなかった。1回だけの検索結果を「これで全部」と決め打ち
   せず、別の角度からもう一度確認する)
   言い換え質問の例(1回目の回答を踏まえて、同じスレッドで追加送信する):
   - radiko Stage1(フォロー中番組の確認):
     「上記の番組について、各番組公式X(Twitter)やパーソナリティ・ゲスト
     本人・事務所の投稿も確認して、番組表だけでは分からないゲスト出演
     情報があれば追加で教えてください」
   - radiko Stage2(リスト外の探索):
     「上記に加えて、各局公式X(Twitter)やアーティスト本人・事務所の
     投稿など、番組表とは別の情報源から分かるradikoでのゲスト出演告知が
     あれば教えて。NHKラジオ第1『らじらー！サンデー』のような定期特番の
     ゲストも忘れずに確認して」
   言い換え質問の回答で新たに見つかった番組は、本体の検索結果に追加する
   (内容が重複していれば無視してよい)。それでも見つからない場合は、
   無理に情報をひねり出さず「該当なし」のままでよい。
4. Grokの回答から、番組名・放送日・放送時間・ゲスト名・URLが分かる情報を抜き出す
   (get_page_textなどでテキスト全文を取得し、スクロールして続きがないか
   必ず確認する。1回の取得で回答が切れている場合がある)
   - 放送日は「本日」に固定せず、Grokの回答に明記されている日付をそのまま
     使う(例: 再放送で翌日になる、収録日と放送日が別、特集番組で放送日が
     本日と異なる、などのケースがあるため。回答に日付の記載がなければ
     「放送日: 検索実行日(YYYY年M月D日)時点の情報、詳細日不明」のように
     不明な旨を明記する)。対象期間が10日間に広がっているため、1つの
     番組でも複数の放送日(例: 毎週火曜など)が該当することがある。その
     場合は該当する放送日ごとに行を分けて記載する
   - URLは「実際にラジオが聴けるURL」を優先する(公式ページ・紹介記事の
     URLは不要)。優先順位は以下の通り:
     1) radiko: ライブURL(https://radiko.jp/#!/live/[放送局ID])や
        タイムフリーURL(https://radiko.jp/#!/ts/[放送局ID]/
        [YYYYMMDDHHMMSS])。Grokの回答に出てくる各局の記事ページ
        (例: 1242.com/takada/ のような局サイトの番組紹介ページ)は
        聴けるURLではないので、そのままでは採用しない
     2) らじる★らじる(NHK): ライブURL
        (https://www.nhk.or.jp/radio/player/?ch=r1 など、r1=第1/
        r2=第2/fm=FM)や、聴き逃し(オンデマンド)URL
        (https://www.nhk.or.jp/radio/ondemand/detail.html?p=... )。
        nhk.jp/p/... の番組情報ページ(例:
        https://www.nhk.jp/p/ml/rs/Z9WGYY3GP5/ )はゲスト確認用の
        裏取りには使うが、出力するURLとしては聴けるURLを優先する
     3) 音泉: onsen.agの番組ページ自体がそのまま視聴ページを兼ねる
        ことが多いので、番組ページURLをそのまま使ってよい
     Grokの回答本文やページ内の出典リンクからread_pageなどでリンクの
     実際のURLを取得して使う。聴けるURLがどうしても取れない場合のみ、
     そのサービスのトップページURL(https://radiko.jp/ 、
     https://www.nhk.or.jp/radio/ 、https://www.onsen.ag/ )を代わりに
     記載し、それも無理なら「URL: 不明」と記載する
5. 【重要】NHKの「ミュージックライン」は月〜金 午後9:45〜の帯番組で、
   翌朝午前10:15〜に前日放送分がそのまま再放送される。そのため対象期間
   内のどの日についても、その日「聴ける放送」には
     a) その日21:45〜の本放送(その日の新規ゲスト)
     b) その日10:15〜の再放送(前日の本放送＝1日前のゲスト)
   の2本が存在し、ゲストが異なることが多い。Grokの回答で日付ごとに
   「ゲスト:○○」が1人しか出てこない場合は、本放送・再放送どちらの
   情報か(あるいは両方载っているか)を確認し、載っていない方があれば
   追加で聞き直して両方を記載する(例:「ミュージックラインの
   [YYYY年M月D日]10:15の再放送と21:45の本放送、それぞれのゲストを
   教えて」)。判断に迷う場合や日付の記載が曖昧な場合は、公式番組ページ
   (https://www.nhk.jp/p/ml/rs/Z9WGYY3GP5/)を直接開き、「これからの
   エピソード(放送予定)」に載っている日付とゲスト名で裏取りする
   (このページには通常、直近1〜2週間程度の放送予定が載っている)。
6. 情報が不足している場合は、検索語を変えて追加で検索してよい
   (NHKで該当が少ない場合、「音楽番組」「バラエティ番組」でそれぞれ分けて
   聞き直す、または「NHK第1」「NHK第2」「NHK-FM」ごとに聞き直すなど、
   検索語を変えて試してよい。放送日やURLが抜けている場合は
   「その番組の放送日とURLを教えて」のように追加で聞き直してよい)
7. 【radiko Stage2のみ2セット実行してAI(Claude)でマージ・重複除去】radikoの
   Stage2(リスト外の探索)についてのみ、上記2.~4.(本体検索+言い換え検索+
   情報抜き出し)を「1セット」とし、これをデフォルトで2セット実行する。
   2セット目は同じ対象期間・同じ質問方針で、できれば新しい会話スレッドで
   独立に行う(同じスレッドの続きだと1セット目の回答に引っ張られやすい
   ため)。Stage1(フォロー中番組の確認)は2セット化・マージは行わず、
   1セットの結果をそのまま8.のまとめに使う。
   (背景: 2026/9/6にradiko・NHKラジオ・音泉すべてで実際に2セット実行して
   比較したところ、radikoは毎回セットごとに拾える番組がかなり異なり
   (片方のセットにしか出てこない番組が多数)、2セット分を突き合わせる
   ことで明らかに網羅性が上がった。一方でNHKラジオ(ミュージックライン・
   らじらー！サンデー)と音泉は、2セット試しても内容がほぼ同じ(ゲストも
   ほぼ一致)で、2セット実行する効果が薄いと判断した。そのため2026/9/6の
   運用見直しで、2セット実行&マージはradikoのみに絞り、NHKラジオ・音泉は
   下記の通り1セットのみとした。2026/9/17にradikoをStage1/Stage2へさらに
   分割した際も、2セット化・マージは引き続きStage2のみに適用している)
   2セット分の生の抜き出し結果を保持したうえで、Grok自身に統合させる
   のではなく、Cowork(Claude)側で以下の基準に沿って重複除去・統合を
   行い、radiko Stage2の完成版リストにする:
   - 番組名+放送日が一致するものは同一の情報として1つにまとめる
   - ゲスト名・放送時間・URLなど詳細情報がセット間で食い違う、または
     一方のセットにしか載っていない場合は、より詳しい・具体的な方を
     採用する。判断が難しい場合は両方の情報を併記してよい
   - どちらか一方のセットにしか出てこなかった番組は、原則としてそのまま
     採用する(片方のセットだけでヒットした、というだけの理由では
     除外しない)
   - 情報が曖昧・矛盾していて無理に一本化すべきでない場合は、「セットA
     では○○、セットBでは△△」のように両論併記のままでよい
   なお、2セット実行してマージしても100%の網羅を保証するものではない
   (Grok検索の性質上、完全な取りこぼしゼロは目指さない)。セットごとの
   中間結果(2セット分)を個別にファイル保存する必要はなく、マージ後の
   完成版のみを9.の手順で保存すればよい。
   NHKラジオ・音泉については、2.の本体検索1回(+4.の抜き出し)の結果を
   そのまま8.のまとめに使ってよい(言い換え検索・2セット目・マージ処理は
   いずれも不要。2026/9/17改善(2)参照)。
   【radiko Stage1/Stage2の統合】Stage1(フォロー中番組の確認)で「ゲスト
   あり」と判明した番組が、Stage2(リスト外の探索、マージ後)にも同じ
   番組名+放送日で出てきた場合は、その番組はフォロー中番組側の情報を
   正として8.の「フォロー中番組」セクションにまとめ、Stage2側の「radiko
   (リスト外)」セクションには重複させない(Stage2側にしか無い詳細情報が
   あれば、フォロー中番組側に補って統合してよい)。
   【Grokの利用上限に関する注意】radiko Stage1(本体+言い換えで計2回)+
   Stage2の2セット分(本体+言い換えで計4回)にNHKラジオ・音泉の本体検索
   のみ(各1回、計2回)を合わせると、1回の実行で最大8回Grokにクエリを送る
   ことになる。Grok(X)の無料枠は「1日20問」までで、同じXアカウントで
   同日に他の用途でもGrokを使っていると、この上限に達して実行が完了
   できないことがある(2026/9/6の試行時に実際に発生)。上限に達した場合は
   無理に続けず、いったん実行を打ち切ってその時点までの結果で完成版を
   まとめてよい。優先順位に迷った場合は、フォロー中番組の確認(Stage1)を
   最優先で完了させ、次にNHKラジオ・音泉、最後にradiko Stage2の2セット目、
   の順で打ち切ってよい。
8. まとめる。以下の順で見出しを分けてまとめる:
   ① フォロー中番組のゲスト情報(Stage1の結果。かつStage2でも重複ヒット
      した番組があれば統合したもの。ゲスト出演が「あり」だった番組のみ
      記載する。ゲスト情報が無かった番組は、その旨も含めて一切出力に
      含めない(「ゲスト情報なし」等の記載は不要。2026/9/18改善参照))
   ② radiko(リスト外の発見。Stage2でマージした完成版から、①に統合済みの
      番組を除いたもの)
   ③ NHKラジオ
   ④ 音泉
   ①・②はまとめて「radiko」という大見出しの下に2つの小見出しとして
   置いてよい。各見出しの中身は、1件のゲスト出演情報につき1エントリと
   して「放送日(曜日) 番組名／放送局 放送時間」を先頭行とし、続けて
   「ゲスト: ○○」「URL: ○○」を記載する形式でまとめる(放送日を番組名の
   先頭につけることで、そのままメモアプリ等にコピペしやすくする。
   2026/9/18改善参照)。1つの番組で複数の放送日がある場合は、放送日ごとに
   エントリを分ける。対象期間が10日間あるため、各見出しの中では放送日が
   早い順(本日に近い順)に並べる
   (NHKや音泉で対象期間内に明確な「ゲスト出演」が無い場合は、その見出し
```

## Grok操作時の注意点(実運用で判明した点)

- Grokの入力欄はページスクロールで座標がずれやすく、座標クリックでの
  入力・送信は失敗しやすい(別の要素に入力されたり、送信ボタンが反応
  しなかったりする)。入力欄・送信ボタンは座標指定ではなく、要素検索
  (find/read_pageなどでテキストボックスや「Grokに聞く」ボタンの参照を
  取得)してから操作する方が確実
- 【重要】上記の要素検索でも、クリック後に本当にテキストボックス
  (`<textarea>`など)にフォーカスが当たっているとは限らない。ラッパー
  のdiv(`<div aria-label="Grok">`など)にフォーカスが残ったまま入力
  すると、入力した文字(特にURLに含まれる「/」)がX.com全体のキーボード
  ショートカットとして解釈され、文字が欠落したり、ページが勝手に
  別タブ(例: x.com/explore)へ遷移したりすることがある。対策として、
  文字入力の直前にjavascript_tool等で入力欄を直接取得してfocusさせる
  のが確実:
  ```
  const el = document.querySelector('[data-testid="grok-input"], textarea, [contenteditable="true"]');
  if (el) { el.focus(); el.click(); }
  el ? el.tagName : 'not found';
  ```
  入力後、送信(Enter)前に`document.activeElement.value`(または
  `.slice(0,N)`)で正しく入力されているか確認してから送信する
- 入力後は必ずテキストが正しい欄に入っているか確認してから送信する。
  誤って「好きではない」などのフィードバックボタン付近をクリックすると、
  評価用のポップアップが開き、そちらに文字が入力されてしまうことがある
  (誤操作した場合はポップアップを閉じて、正しい入力欄から再入力する)
- スクリーンショットが真っ黒になったりタイムアウトすることがあるため、
  応答内容の確認はget_page_text(テキスト抽出)を主に使う方が安定する。
  なお、会話が長くなるとX.com側でDOMが仮想化され、
  `document.querySelector('main').innerText`のようなjavascript_tool
  経由の直接取得だと画面外の古い内容が返ってくることがあるため、
  最新メッセージの取得は素直にget_page_text(専用ツール)を使う方が安定する
- 1つの会話(スレッド)内でサービスごとに続けて質問してよい。ただし
  前の質問が正しく送信できていないと、次の入力と連結されて送信される
  ことがあるので、送信前に入力欄の中身を確認する
- URLは、get_page_textのプレーンテキストだけでは出典リンクの実URLが
  見えないことがある(サイト名のテキストだけが表示される場合がある)。
  その場合はread_page(interactive filter)やfindでリンク要素を探し、
  hrefの値を確認してから記載する
- タブが閉じられてしまっても、会話URL(https://x.com/i/grok?conversation=...)
  さえ控えておけば、新しいタブでそのURLに再度navigateすることで同じ会話に
  戻れる(Grokの会話はタブではなくアカウント側に保存されている)。応答が
  まだ生成中だった場合は、そのまま待てば続きが表示される
